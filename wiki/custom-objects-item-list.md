# Custom Objects: item list screen

Padrão: [ui-list.md](ui-list.md) (modals, row menus, footers), [stack-plugin.md](stack-plugin.md) (autowiring, assets). The item list screen: search by field (alias or label), columns, the item view modal (click on the name) and their traps.

## Item list screen

**Search by field** (`field:value`, like `email:x@y.com` in Contacts). The field is the alias OR the label shown on the screens (case-insensitive; a label with spaces goes in quotes: `"Nome do Curso":Matematica`; accents are fine unquoted). An alias wins over an equal label, and between equal labels the first field by order wins. This applies to the list screen only: the items API parameters stay aliases. Free text with no `field:value` is the old full-text search, unchanged:

**Item view modal** (list of an object's items and the Custom Objects tab of a contact, both rendered by `Resources/views/CustomItem/_list.html.twig`): a plain click on the item's NAME opens, in core's shared modal (`Mautic.ajaxifyModal`, an inline `onclick` on the link, 1100 px wide by a `:has` style in the body), the same detail rows as the item page (core's `Helper/details.html.twig`: category, created by/on, modified by/on, ID; the modified rows only when the item was modified) then the item's field values and the contacts linked to it (up to 50, "Contatos (n)", "50 / n" when more; contact links open in a new tab). The title is `<name> (#<id>)` (the link's `data-header`). Ctrl / cmd / shift click opens the full item page; editing stays in the three-dots menu. Route `mautic_custom_item_details` (`GET /s/custom/object/{objectId}/item/details/{itemId}`, ids `\d+`, so a non-numeric id is 404, not 500), `ViewController::detailsAction`, body `details_modal.html.twig`. Access: the item page's rule (`CustomItemPermissionProvider::canView`, 403 otherwise); the contacts block only for who has `lead:leads:viewown` or `viewother`; 404 for an unknown item or an item of another object. A real item with a 1501-character textarea value and a 150-character name stays inside the modal: `custom-item-modal-long-text.spec.js` (the item name column takes 191 characters; the items API answers 500 above it, not 400). Tests: `scripts/5/test-item-details-modal.sh` (body, 50 limit, permissions through real roles and users, 404s) and `scripts/5/e2e/tests/custom-item-modal.spec.js` (real click, ctrl click, contact tab, both themes).

**Footer of both modals** (item and object): `.bottom-form-buttons` at the end of `CustomItem/details_modal.html.twig` and `CustomObject/details_modal.html.twig` (rules: [ui-list.md](ui-list.md)). `detailsAction` of both ViewControllers sets `canEdit` by calling `canEdit()` of the permission provider and catching ForbiddenException (the edit page's rule). In the HTML the URL is written `\/item\/edit\/<id>` (a live test must search the escaped form). Specs: custom-item-modal and custom-object-modal (footer, both themes, navigation); test-item-details-modal.sh (Editar only with `editown`/`editother`).

**Object list and view pages**: a plain click on an OBJECT's name in the list opens a modal with its fields (`CustomObject/details_modal.html.twig`, route `mautic_custom_object_details` = `GET /s/custom/object/details/{objectId}`, `\d+`, `ViewController::detailsAction`, the object page's permission; columns label, alias, type, required, unique identifier, default value, options; same `:has` widening and cell breaking as the item modal); ctrl / cmd / shift click opens the page. The row's three-dots menu has "Detalhes" (icon `ri-information-line`, like the contacts list) above Edit in BOTH lists (`CustomObjectButtonSubscriber`, `CustomItemButtonSubscriber`, list location only, needs `canView`); the contact tab list keeps its own menu. The fields table is ONE partial, `CustomObject/_fields_table.html.twig`, used by the modal and by the object page (tab Campos, above the chart of items in time); both also have the Clonar tab (wiki/custom-objects-definition-clone.md). The object modal's `.tab-content` has `pt-md` (top only): without it the fields table touches the tabs; side padding would indent it away from the title. Tests: `scripts/5/e2e/tests/custom-object-modal.spec.js` (also the gap >= 10 px), `custom-back-button.spec.js`, `custom-object-detail-order.spec.js`.

**Object edit form (Fields tab)**: the edit / delete buttons of a field in `Form/Panel/_field.html.twig` use core's `Helper/button.html.twig` (ui-list.md). `co-form.js` finds them by `button.btn-edit` (must stay a `<button>`, not an `<a>`) and `[data-hide-panel]`. Delete opens core's confirmation (`Mautic.showConfirmation(button)` reading `data-message`, `data-confirm-text`, `data-cancel-text`, `data-confirm-callback="customObjectsDeleteField"`); the field is hidden and flagged deleted only on confirm, and removed from the database when the object is saved. Test: `scripts/5/e2e/tests/custom-object-field-buttons.spec.js`.

**Owner filter**: a user with `viewown` and without `viewother` sees only the items he created. `CustomItemModel::applyOwnerFilter()` adds `createdBy = :ownerId` (ORM list) or `created_by = :ownerId` (DBAL list) with the user id as the parameter. `andWhere(alias.createdBy, <id>)` with two arguments does not work: the ORM refuses the int (the list answered 500). Tests: `CustomItemModelTest` builds the real ORM and DBAL query builders (a mock accepts the wrong call).
