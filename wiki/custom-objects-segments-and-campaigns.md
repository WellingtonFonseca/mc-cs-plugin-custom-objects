# Custom Objects: segments, campaign events and SegmentItemResolver

The segment filter `in` / `!in` on text fields and its values route, the campaign condition "<object> fields" and the link / unlink action, and `SegmentItemResolver` (which items a segment points at; shared with n8n-dispatch and the Wait action).

{
  "what": "a contact can have many items of one object; a segment only asks whether a matching item EXISTS.   "rules": "the filter list is Mautic's own (ContactSegmentFilterFactory::getSegmentFilters(), after the rewriting the segment build applies); an `or` glue starts a group; inside a group the conditions on this object must hold for the SAME item (intersection); groups and segments add together (union); conditions on contact fields or other objects do not narrow the items (they decide membership, which is respected by skipping the segments the contact is not in); operators the segment applies as NOT EXISTS (empty, neq, notLike, !multiselect, notIn, !between, notBetween; for item names empty, neq, notLike) keep every item except the ones matching the positive condition; a merged filter (custom_object_merge_filter ON) is applied as written through QueryFilterHelper::createMergedItemIdsQuery().",

## Traps

- `in` / `notIn` on an item name with `custom_object_merge_filter` OFF: the segment hands the list to `CustomItemNameFilterQueryBuilder` and `SegmentItemMatcher` as an ARRAY. `QueryFilterHelper::addCustomObjectNameExpression` takes `array|string|null`; callers cast only the scalars. A `(string)` cast turned the list into the name "Array" and "excluding" excluded nobody. With the merge filter ON that path is not used, so test-all (merge ON) never saw it: run `PATH=<shim that adds docker exec -e MAUTIC_CUSTOM_OBJECT_MERGE_FILTER=0> scripts/5/test-segment-in-chips.sh`. With it off the "same item" checks fail by design (they need the merge).
