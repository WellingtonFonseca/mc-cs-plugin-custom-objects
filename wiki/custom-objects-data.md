**String limits**: every string column of `custom_item`, `custom_object`, `custom_field` and `custom_field_option` is VARCHAR(191) in a schema built from the entities (the utf8mb4 index limit; the user confirmed the production schema is the same as the local one). The old migrations 0.0.1 to 0.0.9, the upgrade path of the original plugin, declare some of them as VARCHAR(255): on a schema made only by those, 191 is stricter than the database (it refuses a value of 192 to 255 characters; it never breaks a save). Every `Assert\Length` of these entities uses `StringColumn::LENGTH` (191, `Entity/StringColumn.php`: one place). A limit of 255 lets a value of 192 to 255 characters pass the validation and fail in the database: a 500 on the API and on the form, instead of a 400 or a form error. The limit counts characters, not bytes. Text values of items (`custom_field_value_text`) are `longtext`: no limit. The values of `select`, `country` and `radio_group` fields are text values too (`SelectType` extends `AbstractTextType`, table `custom_field_value_text`, `longtext`): the 191 does not apply to them. Tested on the items API: a text of 192 characters, which cannot be an option, is saved whole in `select` and `country`. Not tested: a short value that is not an option. Only `multiselect` and `checkbox_group` use `custom_field_value_option` (VARCHAR(191)); the API answers 400 "does not exist in the list of options" for a value that is not an option, and an option has at most 191 characters, so there is no 500 and no silent cut there. A new string column needs its constraint at `StringColumn::LENGTH`. The description of an object is rich text (CKEditor): the stored value is HTML, so its `<p>` wrapper counts in the 191. Tests: `Tests/Unit/Entity/StringLengthConstraintsTest.php` (all ten properties, 191 valid and 192 refused, with the limit named in the message; the item name too), `CustomItemTest`, the browser spec `scripts/5/e2e/tests/custom-object-form-length.spec.js` (the object form: alias, names and description; its description is a CKEditor: fill it with `el.ckeditorInstance.setData()` + `updateSourceElement()`, `fill()` on the editable never reaches the textarea).
